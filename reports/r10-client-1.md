# Minecraft 1.0 client, round 1

This round ports the largest class, **RenderBlocks**, including its complete default-runtime 1.0 source delta. The remaining client area is not finished. The next largest class, RenderGlobal, is partially ported, with its particle dependencies implemented. The next step is to finish RenderGlobal integration before proceeding to ModelDragon. No 1.0 model, entity renderer or GUI screen is claimed complete.

## References and boundaries

Read `b181-r10client.md`, `r10-common.md`, `tools/r10/areas.md` and `tools/r10/renames.json`. No AGENTS.md was found in the checkout or the inspected source directories. The 1.0 source directory is missing from this worktree; the read-only reference used was `../beta-rs/tools/retromcp-r10/minecraft/src/net/minecraft/src`. Diffs normalize class/member renames before reviewing behavior. `target/delta-RenderBlocks.txt` preserves that comparison; `target/read_delta.py` can reproduce it.

`tools/oracle10` and `tools/verify10.sh` are not merged in this checkout. Neither was created or modified. No original-bytecode parity is claimed from the Rust regression tests. All Beta crates, both Beta oracle trees and their verification scripts are untouched. All production edits are inside `crates/client10`; no simulation classes, containers or recipes were duplicated. The small potion helper is presentation-only (color and instant-particle selection), with no potion simulation or brewing implementation.

## RenderBlocks implementation

- Dispatch and source geometry for render types 23 (lily pad), 24 (cauldron), 25 (brewing stand), 26 (End portal frame), and 27 (dragon egg).
- Lily-pad coordinate hash uses Java int/long wrapping, float corner arithmetic, exact integer colors and reversed underside winding. Brewing-stand sprites preserve arm order, metadata UV reversal, double trigonometry and narrowed float atlas coordinates. Cauldron interior/water offsets preserve the original float-before-double casts and metadata clamp.
- Portal frames preserve the direction-specific top UV rotation, eye override/reset and final bounds. Dragon eggs share the original eight slices between terrain rendering and the single inventory Tessellator batch; renderItemIn3d includes type 27. Vanilla's empty type-23 direct inventory branch is retained.
- AO now selects own brightness and the block's sampling plane for inset faces on all six sides. Light-emitting blocks bypass AO. Repeater torches use packed lightmap brightness and white vertex color.
- Fluids subtract `(double)0.001F` from the top heights only when the top is emitted, retain those heights for side faces, inset the bottom and four sides, and preserve double division of the widened sine/cosine products.
- Isolated redstone wire now trims every disconnected side. Fences connect to opaque normal blocks except pumpkins, and leave state-derived bounds after rendering.
- Client terrain/item render-property tables include ids 110-122: mycelium, lily pad, Nether brick/fence/stairs/wart, enchantment table, brewing stand, cauldron, End portal/frame, End stone and dragon egg. Mycelium snow-side texture, Nether-wart stage textures and item bounds are included. `Tessellator.set_color_opaque_i` bypasses float color normalization.

Integration limitations: worldgen10 still has the inherited block/material registry in this checkout. A clearly documented client-only light-value bridge supplies the four new emitting block ids; new solid-material neighbor lighting/culling must be rechecked once the blocks worker's registry lands. This change does not create the End dimension, new block gameplay, the enchantment book, or the portal surface tile renderer. Those are separate classes/worker changes. The startup screenshot still visibly labels the game Minecraft Beta 1.8.1 because GuiIngame has not been ported.

## RenderGlobal and required dependencies

- End tunnel sky: original six independent face rotations, repeated 0..16 UVs, packed color 1579032, disabled fog/alpha test, standard alpha blending and no depth writes. The End branch reads the player's dimension id; the End world/provider is not present in this worktree, so this is future integration wiring, not a working End simulation.
- Moon-phase atlas loaded from `/terrain/moon_phases.png`, with all eight 4x2 phase UVs; signed Java remainder and narrowing are preserved for negative/overflowing world times. Sunrise adds the original 90-degree Z rotation; sun/moon/stars share the new -90-degree Y rotation. Void threshold is y=63 and black-box bottom uses depth+65.
- Named factory returns the inserted particle reference (layer/index), applies reduced-particle RNG before distance/name guards, and preserves the large-explosion bypass. Names now include magicCrit, all spell kinds, enchantment-table particles and both drip materials. New potion/eye item fragment icons are read from the source while the simulation item registry is pending.
- Ported EntitySpellParticleFX, EntityEnchantmentTableParticleFX and EntityDropParticleFX constructors, independent entity/Math RNG draws, ticks, textures, motion, expiry and brightness. The spell render method intentionally leaves its unused clamp result unused; its scale does not animate. Drips use the original 40-tick hanging phase and lava packed brightness 257. EntityBreakingFX's constructors and layer-2 jittered quads were audited; the inherited geometry is retained.
- Auxiliary effects 1007-1009 and 2002-2004: ghast sounds, eight bottle/eye fragments, 100 tinted normal/instant spell particles, the ordered two-speed eye portal ring, and 20 paired smoke/flame bursts. Tint RNG occurs only for a successfully created spell. The client palette implements the source's nine enabled presentation predicates and original repeated float color accumulation; no gameplay effects are created.
- Minimal dependent settings wiring: RenderClouds/Particles enum options, save/load/cycle/labels, video-menu buttons and cloud suppression in Nether/End and at Short/Tiny render distances. Full GameSettings/GuiVideoSettings/EntityRenderer deltas remain unaudited.

**RenderGlobal remains Partial.** Its synchronous `World.rand` consumption cannot be represented exactly by the inherited asynchronous event bridge, which intentionally replays non-consuming auxiliary snapshots; ordinary particle callbacks currently use an adapter RNG. Before claiming completion, integrate source-ordered RNG consumption with the world worker and compare the callback stream and final World RNG state. The inherited worker's time-budgeted whole-chunk rebuild scheduling also has not been replaced with the 1.0 `updateRenderers` in-frustum allowance change from 3 to 30 section renderers. Review dimension/world-height integration and integer third-person entity visibility when those worker/settings changes land. The new TileEntityRenderer callback is empty in the source; no runtime lighting behavior was added for that no-op. No port of profiler/display-list/occlusion allocation is claimed for the wgpu adapter.
