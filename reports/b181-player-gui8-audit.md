## Player replay fixes

`EntityPlayer.onDeath` tests whether the DamageSource is non-null, not whether it names an attacker. `player_death` now receives source presence; the existing living-death dispatch passes `Some(source)`. Environmental damage therefore keeps the original horizontal death motion. The only shared living changes also recognize a source whose entity ID equals the live victim: player attribution, zero-distance position lookup/random draws, and self-kill statistics work while the world temporarily removes the player from its map. No general entity physics, projectiles, mobs or models were rewritten.

`playerdamage8_181` calls the original damage method for 2,400 environmental and self-owned-arrow cases, mixing lethal/nonlethal damage and hurt cooldowns. It compares health/hurt state, motion/bounds, attacked yaw, dimensions, exhaustion, attack/velocity flags, entity and Math.random state, ordered statistics and world events: 399,208 bytes EXACT. The Rust inherited combat fixture also now passes the same indirect arrow/owner DamageSource as Java, rather than its old entity-argument compatibility call. This corrects only that Rust fixture input. All six affected full-player scenarios are EXACT, including combat frame 21 and its remaining 400-tick replay.

The saved-mode audit includes original controller factory/flip yaw for every successful launch. Both spawn/respawn flip call sites now use the same nonzero policy as worker capability initialization. These changes only replace the existing mode argument; world/dimension/save algorithms remain unchanged.
