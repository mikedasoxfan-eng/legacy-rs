# b1.8.1 player-gui, round 7

The complete area remains **NOT DONE**. This round completes the vanilla class deltas of **PlayerController, PlayerControllerSP, InventoryPlayer and GuiSlotStatsGeneral**. ## Changes

- Controller factories use the existing player constructor and original provider dimension. Survival flips current yaw to -180; creative inherits the base no-op. Production spawn and respawn now call that policy. Direct survival removal on air retains the original failure instead of silently returning false.
- Inventory NBT construction preserves the original 32,000-entry item-array bounds failure, before checking whether the slot is used. The exhaustive fixture also verifies the partially loaded inventory after failure.
- Inventory initialization/update redirect when the controller mode changes, including the reverse creative redirect. Inventory screens retain the original overridden death-update policy and hidden achievement/stat button callbacks. The replacement screen appears immediately through the existing GUI action system, then receives its world-thread acknowledgement; the acknowledgement does not recreate/close it. The old close clears the carried stack before the new screen draws.
- Inventory-open statistics now come from one screen-opening path. Opening creative inventory through the inventory key preserves the original GuiInventory-then-GuiContainerCreative constructor credit. No world-side open-inventory achievement event is also emitted.
- Live inventory figure snapshots sample the existing Entity.brightness API. Hurt overlays use that brightness. A literal death-pose bridge is included in the existing GUI figure adapter, but its four diagnostic captures are not pixel EXACT and the class is not credited Done.
- General-stat rows share their actual production draw arguments with the checker. A newly found decimal double-rounding bug is fixed by formatting the original binary double directly.
