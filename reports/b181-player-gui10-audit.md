# Player-gui round 10 source audit

Both complete GuiMainMenu, RenderEngine and StatFileWriter decompilations were compared with `git diff --no-index`. The protected b173 sources were read and never edited.

## GuiMainMenu

The constructor reads UTF-8 splashes, trims/filter empties, and retries the excluded Java string hash. The retained production static JavaRandom has the same stream: mainmenu10_181 checks 1,000 actual constructor strings and the subsequent nextLong. Constructor defaults, the new integer panorama timer and the retained float update counter are represented directly. The original update method increments both; 40,000 callbacks include signed integer wrap and float-counter precision boundaries. Key callbacks do nothing and the screen does not pause.

initGui allocates a transparent 256-square panorama texture and retains the existing button layouts, holiday overrides, hide-quit policy and sessionless disabled multiplayer button. The production snapshot texture supplies that storage; it is overwritten by the original framebuffer copies before the final crop. Holiday detection now uses local Calendar-compatible dates through chrono::Local, correcting the inherited UTC implementation. mainmenu10_181 checks 10,000 original layouts and sessionless key callbacks; 60,000 singleplayer button actions compare display/shutdown counts. Multiplayer actions are outside the task scope.

The new panorama is the source's 64 translated cube samples, six faces per sample, 120-degree GLU perspective, sine tilt and yaw, eight copies and blur passes, followed by the original crop, gradients, logo, splash and labels. LWJGL's float-angle/double-trigonometry/float-result sequence is retained literally. Every title capture uses the production renderer.

The first precision gap was in glRotatef: 2,784 of 6,144 observed float matrix elements differed when emulated with double rotation arithmetic. Native driver matrices matched all 6,144 elements, reducing the cube difference to one pixel. The remaining rasterization difference propagated through the blur to 24 ordinary-title pixels and three anaglyph-title pixels. Reassociation and alternate triangulation experiments were rejected and removed.

The accepted implementation performs the original cube's fixed-function OpenGL matrix and array-draw operations in a hidden, thread-local Windows GL context and a single-sample RGBA8 framebuffer. It uses the port's already-loaded and already-anaglyph-converted textures, imports the current framebuffer's color/alpha, and preserves the first sample's inherited color mask and depth-test policy. Native resource creation checks framebuffer completeness and restores the previous current context. wgpu still performs framebuffer transfers, all eight blur passes, the final crop and the rest of the GUI. The cube image is transferred through an ordinary nearest-sampled wgpu texture, preserving the destination alpha. Panorama face readbacks are cached and invalidated by texture replacement.

GuiPanoramaProbe10 optionally calls the actual original private cube and blur methods and observes their intermediate framebuffers. The production probe reads its existing framebuffer without changing it. At time zero the cube and every one of the eight blur stages compare with zero differing RGB pixels. Eight additional full-screen original captures cover panorama times 0, 1, 7, 37, 100, 400, 999 and 2000. Feature scenes also cover pack reload and post-world anaglyph masks. The new title block explicitly supplies sessionless before opening the menu: earlier world fixture commands restore a Java Session for EntityPlayerSP, so this resets the original to the same singleplayer-only input as the port. RGB and alpha comparisons have zero tolerance.

This native adapter is limited to GuiMainMenu. No world, entity, hand, fog, FOV or lightmap renderer is changed. Windows/OpenGL and canonical single-sample captures are the verified path. Existing multisample and small-window paths remain available; arbitrary out-of-window OpenGL copy texels are undefined and are not claimed byte identical. The adapter adds GL context/resource operations and GPU readback to each title frame; face textures are cached, but frame-time performance was not benchmarked. Overall framebuffer/renderer lifecycle completion remains under RenderEngine and the integrator's Minecraft worker.

## RenderEngine

The source delta changes the dynamic image map from HashMap to MCHash, increases the image byte buffer to 16,777,216 bytes, exposes clamp/blur flags, adds %blurclamp% to getTexture and refreshTextures, broadens getTexture's exception catch, adds clamp around getTextureContents' %blur% read, and renames image/color helpers.

This round corrects the production texture prefix decoder: it tests exactly one prefix, adds %blurclamp%, and retains inner prefixes as part of the resource name. Its earlier loop incorrectly consumed stacked prefixes. Actual original getTexture calls cover 2,000 names across the ordinary, clamp, blur, blurclamp and stacked-prefix branches. An observing upload adapter records the requested resource name and active flags; cache identity, one upload and post-call flag reset are checked. The shared GL stub only gains an otherwise unused texture-name allocator; existing recording paths are unchanged.

Complete getTextureContents cache identity/failure behavior, mutable public-flag failure retention, dynamic-image MCHash refresh/deletion ordering and buffer-limit exceptions still need a unified production API and original trace. URL skin download methods remain out of scope. Existing conversion, animation and framebuffer tests remain required. RenderEngine is NOT DONE; solving the title capture does not imply this whole class is complete.

## StatFileWriter

The b181 source delta consists of Jdom API renames, the achievement-parent method rename and the renamed send callback. Existing synchronization, stat addition, achievement membership and parent checks already cover those call paths. The remaining serializer/parser entry points were audited here.

The parser now distinguishes syntax rejection (a new empty map) from unchecked schema/number exceptions and checksum rejection (null). StatsSyncher catches the unchecked exceptions at the file boundary, as in the source. JSON strings preserve UTF-16, duplicate fields replace prior values, and getFields copies follow Java 8 HashMap bucket/tree ordering. J_JsonStringNode is Comparable; lexical ranks provide exactly its equal-hash ordering to the existing JavaHashSet tree implementation. A minimal initial-capacity constructor was added to that existing implementation; no default world-set algorithm was changed.

The parser preserves Argo's first-character whitespace behavior, literal control-character acceptance, restricted escape syntax, signed/Unicode four-character hexadecimal escapes, numeric token grammar and the original uppercase-E/second-dot exponent bug. Integer parsing uses Java 8 BMP decimal digits, signed boundaries and wrapping stat IDs. String and number nodes remain distinct, so a numeric checksum raises the original schema exception. Unknown IDs are ignored before checksum accumulation; duplicate statistics still contribute each checksum term and the last map value wins.

statfile10_181 calls the actual original parser for 3,050 schema/grammar/checksum/object-order cases. It also calls the actual original serializer on 1,000 supplied ordered maps, including null user/session, empty maps, null values, signed values, zeroes and unescaped user strings. The production serializer shares the literal formatting implementation, and every output byte matches for these supplied iteration orders.

StatFileWriter remains NOT DONE. Production file maps still use their inherited sorted-ID ordering rather than JVM StatBase identity-hash iteration. Constructor failure/migration boundaries, arbitrary hostile malformed strings (including original nontermination), arbitrary JVM charset/session behavior and complete static entry-point map types are not exhaustively credited. No serialization-order tolerance or checksum relaxation was introduced.
