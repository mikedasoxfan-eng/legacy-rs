# Release 1.0 world port, round 1

Source review uses the Release 1.0 MCP sources at `C:/Users/logiu/Desktop/Projects/minecraft/beta-rs/tools/retromcp-r10/minecraft/src/net/minecraft/src` and the Beta 1.8.1 sources in this worktree. The Release source directory and `renames.json` are absent in this worktree. No oracle or verification script was created or changed.

The class table records 95 Ported and 44 Partial classes, with a bytecode-check target for all 139. The implementation adds End terrain and decoration, Nether fortress generation, stronghold portal rooms and chest corridors, the Release biome graph, decorator settings, freezing/snow checks, world tick/light changes, queued region writes, pending tick persistence, NBT copy/name support, and the world profiler sections. Existing compatible code is retained where the Java delta is a rename, a control-flow rewrite, or replacing the constant world height with a field whose Release value is 128.

`Ported` means the source behavior of the class is represented, including inherited compatible code. It does **not** mean bytecode equivalence has been established. `Partial` identifies remaining behavior or integration work. In particular, End crystals/dragons and village inhabitants are typed generation requests, not live entities. The entities worker must consume these requests in the original constructor/order context. Natural spawning still uses its inherited selection algorithm; the new provider list and World weighted-selection entry points are available but need the Release SpawnerAnimals integration. These limitations prevent declaring the complete Release world simulation exact.

Validation: `cargo test -p worldgen10` passes all 38 tests (21 library tests and 17 integration tests, plus binary/doc targets). `cargo build --release` passes for the workspace. `target/release/beta.exe --mc 1.0 --seed 42 --no-save --shot target/r10-smoke.png --shot-ticks 60` exits successfully; the screenshot was inspected and shows terrain, trees, entities, the player hand, and HUD. The inherited HUD still says Beta 1.8.1; branding/rendering changes belong to the client area. Logs are `target/r10-tests.log`, `target/r10-build.log`, and `target/r10-smoke.log`.

Tests cover End island/void repeatability, accepted and rejected spike footprints/RNG, negative-coordinate biome query tiling, stronghold portal retries and piece limits, fortress graph limits and one-shot spawners, duplicate hash-map behavior, profiler aggregation/decay, named NBT/MUTF-8/canonical NaNs, pending tick indexes, no-sky light queries, queued-write replacement, and region-file flush/readback. Inherited integration tests were repaired for their existing typed jukebox support, non-null empty NBT arrays, zero Overworld ambient light, and the new asynchronous save contract.

Cross-area edits are restricted to dependencies: block property entries for generated IDs 110–115/120–121 and plain placement callbacks; Release biome spawn-list data and handling unavailable entity factories; sapling notification constructors; World-owned methods located under `entity/`; `EnumAction`'s Drink ordinal; client saved-light/biome tint adapters, save-list hardcore/size data, zero TexturedQuad texel offsets and TextureOffset, and shutdown save flushing. Full new block behavior, entity behavior, new models, and GUI changes remain with their owners. The grass/leaf/vine color adapter implements the swamp tint, but the blocks worker must supply the Release grass sampling behavior.

NBT limitations apply to the table below: Rust strings cannot retain unpaired UTF-16 surrogates; payload tags do not carry every Java child-name/alias identity; compound accessors retain inherited permissive wrong-type behavior; the parser retains its depth bound. Byte-array equality is structural here, whereas Java's source uses array identity. Compression and stream-close/exception behavior also require Java checks. Asynchronous I/O preserves queued data/order but does not reproduce Java thread priority or interruption semantics.

No commit was made. Run `bash target/commit-r10-world.sh` to stage the exact code/report paths and create the requested commit. The script does not stage logs, screenshots, old-version crates, or tools.
