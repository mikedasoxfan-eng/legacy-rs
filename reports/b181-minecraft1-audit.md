# Minecraft round 1: complete source-delta audit

Compared `tools/retromcp/minecraft/src/net/minecraft/client/Minecraft.java` with `tools/retromcp-b181/minecraft/src/net/minecraft/client/Minecraft.java`. This table includes every changed method and the changed branches inside it. Rename-only changes are identified explicitly. **Minecraft is NOT DONE.** An EXACT input or callback boundary does not imply an EXACT complete application lifecycle.

Evidence keys below refer to sections of `tools/verify_minecraft181.sh`, which uses the original deobfuscated b181 jar on Mojang Java 8u51:

- **runtick181**: `Mode_runtick181` invokes the original, unmodified `Minecraft.runTick`, `clickMouse`, `sendClickBlockToController`, middle pick and focus methods. 2,080 ticks, 26 survival/creative scenarios. The Rust checker uses the production `minecraft_input::run_tick` and `worker::MinecraftHost`, including the production player's actual controller/item methods. Each record contains input events and polled physical keys, followed by screen/focus, drops, controller click callback counts, swing calls/state, every inventory stack, every binding state/count, settings, both counters, item-use state/count, controller mining state and world-tail callback counters. World ticking/rendering/platform callbacks are recording substitutes; this proves their invocation policy, not their internals.
- **minecraftpreload181**: calls original private `preloadWorld` by reflection. 128 cases cover missing/present loading renderer, missing/present player, double-to-int coordinate truncation, signed coordinate overflow, missing/present load-provider focus and both controller preload policies. The production `scenario::preload_grid` supplies the Rust coordinate/progress/lighting loop. Initial/final loading messages and provider fields are boundary observations; the entire open-world transaction is not claimed.
- **minecraftdebug181**: calls original `Minecraft.debugInfoEntities`, original `EffectRenderer.getStatistics` and original `World.getDebugLoadedEntities`; 10,000 fixtures. Production `minecraft_input::debug_entities`, the existing three-layer particle count, and worker-provided loaded-entity count supply the Rust line.
- **controllerinput181**: retained 2,800 click/held/repeated-use transitions, complete inventory/controller, ordered effects, RNG and dropped-entity snapshots (2,681,544 bytes).
- **keyregistry181**: retained 20,000 global registry events, four settings instances, stale/duplicate bindings, rebuild/release, wrapping overflow and consumption.
- **controllerlife181**: retained 1,000 actual controller factory/flip cases, 20,000 partial/reset boundaries and original use-release callbacks. This does **not** invoke the complete Minecraft changeWorld or respawn method.
- **worldcallbacks181**, **worldseed181**, **select8_181**: retained actual create/select-screen callbacks, seed parsing and WorldSettings, saved GameType/controller selection. These do **not** invoke the complete Minecraft.startWorld transaction.

## Limits and ownership

The fresh/stale fixture supplies observations well away from 200 ms, not matching clock timestamps. Recording screens deliberately avoid rendering and record callback policy. Recording world tick methods avoid rerunning terrain/entity simulations inside this focused input check; policy is shared with production, and retained controller checks independently compare complete effects/RNG/drop state. Neither fixture replaces Minecraft.runTick itself.

The minimal worldgen181 edits belong to Minecraft: expose its existing click adapter with passive callback-result bits, factor its held-dig dispatch, and factor its preload coordinate/progress loop. No other block/entity/item algorithm, shared oracle fixture, Oracle.java, GUI class, renderer/lightmap algorithm, or b173 code/verifier was edited. No full verify181 run is claimed. Rows marked missing keep the class NOT DONE.
