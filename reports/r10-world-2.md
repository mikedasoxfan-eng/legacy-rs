# Release 1.0 world port, round 2

The round-2 audit covers all 139 requested classes in task order. **0 Done; 139 Not done.** The required original-bytecode harness `tools/oracle10` and suites `tools/verify10.sh` / `tools/verify_*10.sh` are absent. No harness, suite, or coverage declaration was fabricated. Source review and Rust regression tests cannot establish original-bytecode exactness.

Source-status count: **122 Ported, 17 Partial**. The table separately labels source status: Ported means the Release delta is represented by existing or updated code, including merged dependencies; Partial identifies source/model gaps. Even Ported rows require the exact check in the last column before they can become Done. The remaining model gaps are substantive, so this report does not claim all source work is complete.

Source reference: `C:/Users/logiu/Desktop/Projects/minecraft/beta-rs/tools/retromcp-r10/minecraft/src/net/minecraft/src`. Compared against the worktree's Beta 1.8.1 MCP sources using `tools/r10/renames.json`. Renames and removals of unused helpers were separated from behavior changes. Prior geometry/algorithms are retained where their Release delta is already represented; round 1 remains the implementation history.

This round closes the former live-entity integration gaps. End population constructs the dragon before its yaw draw, allocates its seven parts through the merged constructor, and joins the parent synchronously. Spikes construct and join crystals before the bedrock cap, preserving the constructor yOffset. Village placement constructs, professions, positions and joins inhabitants at the persistent clip counter. Generation observation vectors remain available for diagnostics; no consumer should replay them as spawn commands. Fortress overrides now use the registered `LavaSlime` name. End coordinate arithmetic wraps like Java. Chunk light writes mark modified even when the provider suppresses Sky storage. Noncompound root reads finish reading the tag before type rejection, preserving EOF precedence.

The sole cross-area dependency edit is `enchantment.rs`: bind the world-owned IEnchantmentModifier interface to the merged registry and EnchantmentHelper traversal. Registry entries now have stable addresses, traversal executes callbacks in source order and preserves the callback prefix before a malformed later tag fails. The public value-returning registry getter remains available.

Remaining source/model work: named/shared/null/UTF-16 NBT graphs and equality; write-time list type mutation; wrong-type getter and stream-close failures; shared pending-save/backing-array aliases; Java I/O priority/interruption/scheduling; biome cache array aliases/lifetimes and process-wide decorator guard; nullable provider wrappers; mutable World height and alternate-constructor/reference behavior. These are recorded per class below. Rendering, full End client transitions and unmerged entity-specific behavior stay with their area owners.

Validation: `cargo test -p worldgen10` passed **68 tests (47 library, 21 integration)**; binary/doc targets also passed. `cargo build --release` passed for the whole workspace. `target/release/beta.exe --mc 1.0 --seed 42 --no-save --shot target/r10-smoke.png --shot-ticks 60` exited successfully. The screenshot was inspected: forest terrain, trees, HUD and player hand render correctly. The inherited Beta 1.8.1 label is a client-area issue. Logs: `target/r10-world2-tests.log`, `target/r10-world2-build.log`, `target/r10-world2-smoke.log`; image: `target/r10-smoke.png`.

New regressions exercise origin-only live dragon and seven-part IDs/seeds, crystal live/chunk membership, every village orientation/profession with clipped resumption, fortress list ordering and live factories, root-read consumption/EOF precedence, and enchantment callback singleton identity/order/failure prefix. These tests do not substitute for the bytecode oracle.

No commit was made. `target/commit-r10-world.sh` stages only this round's exact source/report paths and contains the requested identity and coauthor trailers. Old-version crates, old oracles and old verification suites were not edited.

## Planned exact checks when the shared oracle arrives

For each row, add `tools/oracle10/Mode_world2_<Class>.java`, dispatch mode `world2_<Class>`, and a Rust comparison against the original 1.0 jar. The proposed suite `tools/verify_r10world2.sh` must emit `== world2 <Class>` for each row, create output directories using `mkdir -p`, avoid `set -e`, retain failure status, and run from `tools/verify10.sh` before its final pflush. These files are deliberately not created while the shared harness is missing.

Use seeds 0, 1, 42, -1 and signed-long extremes where RNG applies; include positive/negative and boundary coordinates. Compare raw blocks/metadata/light/height arrays, ordered traces, serialized payloads and exact floating-point bits, with both RNG internal state/Gaussian cache and entity seed-source state after each phase. Trace entity IDs, constructor ordering, live/chunk membership and generated-profession values. Profiler tests need explicit timestamps; cache/I/O tests need controlled clocks and deterministic scheduler barriers. Exercise the failure and alias cases named per row, not only the passing paths. Retain original compressed bytes for compression checks; sorted canonical NBT is insufficient for iteration/name/identity checks.
