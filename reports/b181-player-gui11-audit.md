# Player-gui round 11 source audit

The complete original b173/b181 StatFileWriter and RenderEngine sources were compared with `diff -u`. Read-only diffs are retained in target/statfile11-source.diff and target/renderengine11-source.diff. No b173 source, crate, oracle or verifier was edited.

## StatFileWriter

The b181 delta is the Jdom parser/get-array/get-fields/get-text/get-string API renames, the achievement-parent accessor rename and beginSendStats rename. Round 10 schema/serializer evidence and the retained StatsSyncher state/achievement/thread replay cover these changed calls. Round 11 closes the constructor and input boundary audit.

The constructor first attempts a single stats-directory mkdir and ignores failure. It then enumerates the parent: a failed File.listFiles is null and the array length access throws NullPointerException. The Rust checked constructor now fails at this same point, before user/session handling. Root files, missing roots, a stats path occupied by a file, matching root-level files and directories, preexisting destination files/directories, failed renames, ignored nonmatching .tmp names and null sessions after migration are observed in ten actual original constructors. The disk snapshot includes directory types and every file byte. The background receive is joined only for observations; production keeps the inherited asynchronous protocol.

Parsing accepts Java UTF-16 input directly. Source audit plus 3,859 new traces covers truncations at every position of a real file, all 256 control/byte characters, escapes and partial hexadecimal escapes, lone surrogates, numeric grammar and malformed schema. Together with the retained 3,050 cases, this distinguishes syntax errors returning a new empty map, checksum rejection returning null, unchecked path/type/number/empty-object exceptions, and duplicate/map-copy order. A bare \u at EOF has StringIndexOutOfBoundsException because the original reader returns -1 for its four-character read; short nonempty hexadecimal reads instead become syntax rejection.

Argo casts EOF to U+FFFF inside unclosed strings and never returns. The original fixture runs these calls on disposable daemon threads with a bounded join, stopping them after observing nonreturn. The checked Rust observation API reports Nonterminating; the production file boundary parks forever for this outcome. This preserves the original nonreturn behavior without reproducing its unbounded heap growth. A truncated escape itself returns syntax rejection rather than entering the unclosed-string loop. This is a liveness observation, not a returned vanilla exception.

The canonical target is Mojang Java 8u51 on Windows, whose default charset is Cp1252. FileReader/BufferedReader removes CR, LF and CRLF when concatenating lines. FileWriter encodes windows-1252, replacing unmappable BMP characters/lone surrogates with '?' and a supplementary pair with one '?'. All 256 byte decodes are exact. MD5String calls getBytes without a charset and passes Java String.length to MessageDigest.update. Supplementary characters in the checksum salt therefore produce IllegalArgumentException when the encoded byte count is shorter than the UTF-16 count. Eight direct checksum and 128 original UTF-16/encoded serializer cases cover ASCII, mapped/unmapped BMP, lone surrogates, supplementary pairs and null values; 1,000 retained supplied-order serializers remain byte identical.

StatBase inherits Object.hashCode. Its production HashMap iteration depends on JVM identity hashes, which are runtime inputs and can differ between original game processes. The task explicitly excludes this irreproducible iteration input, like clock seeds. The port continues to choose sorted IDs for its local disk map; it does not claim identical bytes to an independently launched JVM's independently chosen order. For a supplied iteration order the complete JSON, CRLF, unescaped user/session strings, zero/null/signed values and checksum bytes are EXACT. Checksum verification is unchanged; no file-output normalization is used to prove the serializer.

## RenderEngine

The complete delta replaces the dynamic HashMap with MCHash, enlarges imageData from 1,048,576 to 16,777,216 bytes, exposes mutable clamp/blur flags, adds getTexture/refresh %blurclamp%, broadens getTexture's exception catch, clamps the getTextureContents %blur% branch, and renames image/color helpers. The retained full color/animation/framebuffer checks cover the renamed algorithms. Online skin/image downloads remain outside the repository's singleplayer scope; useMipmaps retains vanilla's singleplayer default false.

The production Engine state is shared by the original-bytecode comparator and the GuiRenderer upload adapter. GuiSystem registers named textures and refreshes through it. Texture-name and contents caches are independent and return the original name/array identities. Contents remain ARGB, unaffected by anaglyph conversion. Refresh mutates existing arrays, retains stale tails when an image shrinks, and preserves partial writes and flags if a larger image overflows the old array. Exactly one prefix is interpreted. Contents deliberately does not recognize %blurclamp%; its initial %blur% branch sets both flags, while its refresh branch only sets blur.

The flags are mutable state. Success clears only the branch-specific flags in getTexture/getTextureContents; refresh clears both after each successful resource. IOException retains flags, caches a missing-image array on initial contents reads and skips the failed resource on refresh. Unchecked exceptions escape contents/refresh; getTexture catches them and allocates a second name for the fallback, retaining failed-branch flags. A resource stream whose read throws during ImageIO's initial sniff can return a null decoded image instead of propagating IOException; the fixture observes that NullPointerException boundary separately from a stream whose close throws IOException. Cache hits do not reread, reupload or clear externally changed flags.

Dynamic images retain shared mutable image references. Refresh uploads them first in the key set returned by MCHash.func_35860_b, then the named resources, then cached contents. Named/contents map replays use UTF-16 lexical ranks for String.compareTo on equal-hash tree bins, with 32 deliberately colliding resource names checked against the original. Deleting a texture removes its dynamic-map key but leaves the named cache entry. The implementation reuses the existing b181 JavaHashSet; the only owner API addition is remove, including Java 8 tree-node deletion/rebalancing/untreeification. Existing add/iterate callers are unchanged. The removal algorithm was audited against the locally installed Java 8 HashMap source; the original 8u51 oracle proves 64 deliberately colliding/nonsequential/reused names and each subsequent refresh order. A separate 180-image trace covers caller mutations, ordinary names, deletion and resize order; 96 mixed refresh transactions cover ordering and early failure with both cache types.

The original unoverridden setupTexture/createTextureFromBytes methods prove 12 image-buffer boundaries: the old 1 MiB limit is exceeded successfully, 16 MiB is accepted, the next column overflows, null images retain the previous state, zero/negative byte arrays and oversized source arrays fail at their original stages. ByteBuffer.clear/put/position/limit state is recorded, including failure retention. The production buffer limit is enforced before uploads, including the existing raw GPU write adapter.

The oracle replaces the constructor's inherited AWT missing-text raster with a deterministic image to observe which image identity/content reaches the upload adapter. It also records resource names, active flags, decoded ARGB arrays, dimensions and upload identities. This is an API fixture, not a screenshot substitution. Retained full pixel/color comparisons cover the existing image conversion and actual graphical adapter.

The GUI regression exposed two adapter lifetimes that had previously been implicit: the native panorama's frame-local transfer must bypass the dynamic registry, and framebuffer copies must apply the blur callback's GL_LINEAR sampling after refresh resets the snapshot texture. Both are corrected in gui/render.rs, without editing GuiMainMenu or its cube implementation. There are no entity, particle, world/chunk, lightmap, fog, FOV, terrain, save or Minecraft-loop changes.

The shared headless GL11 stub receives only two previously absent operations: glTexImage2D records the same uploaded-byte field as glTexSubImage2D, and glDeleteTextures is a no-op storage adapter. Existing recording methods, Oracle.java, world fixtures and listeners are unchanged. Actual original RenderEngine bytecode drives every new transaction.
